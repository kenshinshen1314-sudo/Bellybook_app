## [2025-01-13 19:50] - US-005: 设计IndexedDB数据模型
**Implemented:**
- Created src/db/schema.ts with complete IndexedDB schema definition
- Defined 5 object stores: users, meals, syncQueue, dailyNutrition, cuisineUnlocks
- Created TypeScript types: UserProfile, UserSettings, Meal, MealAnalysis, NutritionInfo, SyncQueueItem, etc.
- Configured indexes including compound indexes (userId_date, userId_date for dailyNutrition)
- Implemented createObjectStores() function for DB initialization
- Added handleMigration() function for future schema migrations
- Created utility functions: generateId(), createDailyNutritionId()

**Files Changed:**
- src/db/schema.ts - New file with complete database schema and type definitions

**Learnings:**
- IndexedDB uses object stores (not tables) with keyPath for primary keys
- Indexes enable efficient queries on non-key properties
- Compound indexes allow querying on multiple fields together
- Auto-increment keys useful for derived/composite keys
- Version migration pattern: oldVersion → newVersion in onupgradeneeded
- Separate profile and settings types for cleaner separation of concerns

**Gotchas:**
- IndexedDB is async - all operations return promises (need wrapper like 'idb' library)
- onupgradeneeded only runs once per version - schema changes require version bump
- Index names must be unique per store
- Chrome DevTools Application tab shows IndexedDB contents for debugging
- Safari has storage limits (~50MB) - need to manage image storage carefully

- Created src/db/index.ts with complete database wrapper
- Implemented operations for all 5 stores: users, meals, syncQueue, dailyNutrition, cuisineUnlocks
- Key operations: get, getAll, add, update, delete, getByDateRange, getUnsynced, markSynced
- Sync queue processing with retry logic and error handling
- Utility functions: clearAll, getDbSize, closeDB
- Full TypeScript typing with DBSchema interface

**Files Changed:**
- src/db/index.ts - New file with complete IndexedDB wrapper (~500 lines)
- package.json - Added 'idb' dependency

**Learnings:**
- 'idb' library provides Promise-based API for IndexedDB (much cleaner than raw API)
- DBSchema interface enables full TypeScript typing for all DB operations
- Compound indexes accessed with tuple syntax: [userId, date]
- openCursor() allows efficient iteration over large result sets
- Transaction-based operations ensure atomicity
- Index names in DBSchema must match index names in schema.ts

**Gotchas:**
- All IndexedDB operations are async - must use await
- Cursor iteration requires manual loop with continue()
- Transaction mode matters: 'readonly' vs 'readwrite'
- Need to handle upgrade scenario (onupgradeneeded) for schema changes
- Browser storage limits vary - Safari ~50MB, Chrome ~6GB (with quota)
- Consider cleanup strategy for old images in meals (US-020)
